## 🐛 Как сообщить о баге

1. Проверьте [существующие Issues](https://github.com/elthebestdevelopman-cyber/XiaoHyperCleaner/issues) — возможно баг уже репортили
2. Если нет — создайте новый Issue с лейблом `bug`
3. Заполните шаблон:

```
Модель: Xiaomi Redmi Note 10 Pro
Прошивка: MIUI 14.0.4
Android: 13
Проблема: [краткое описание]
Шаги воспроизведения:
1. ...
2. ...
Ожидаемый результат: ...
Фактический результат: ...
Лог: [прикрепите xhc.log через меню ⋮ → Поделиться логом]
Скриншот: [если возможно]
```

**Без лога багрепорт обрабатывается в последнюю очередь.**

## 💡 Как предложить новую функцию

1. Создайте Issue с лейблом `enhancement`
2. Опишите:
   - Какую проблему решает функция
   - Как она должна работать
   - Есть ли аналоги в других приложениях
3. Дождитесь обсуждения перед началом разработки

## 🔀 Как сделать pull request

### Подготовка

1. Форкните репозиторий
2. Клонируйте форк:
   ```bash
   git clone https://github.com/ВАШ_ЛОГИН/XiaoHyperCleaner.git
   cd XiaoHyperCleaner
   ```
3. Создайте ветку для фичи:
   ```bash
   git checkout -b feature/название-фичи
   # или для багфикса:
   git checkout -b fix/название-багфикса
   ```

### Разработка

4. Внесите изменения
5. Убедитесь что код компилируется:
   ```bash
   ./gradlew assembleDebug
   ```
6. Запустите тесты:
   ```bash
   ./gradlew testDebugUnitTest
   ```
7. Если добавили новую функциональность — добавьте тесты

### Отправка

8. Закоммитьте изменения с понятным сообщением:
   ```bash
   git add .
   git commit -m "feat: добавлен DNS-фильтр с предупреждением"
   ```
9. Запушьте в форк:
   ```bash
   git push origin feature/название-фичи
   ```
10. Откройте pull request из вашего форка в `main` ветку основного репозитория
11. Заполните шаблон PR:
    - Что сделано
    - Зачем
    - Как тестировалось
    - Скриншоты (если UI)

### Ревью

12. Дождитесь ревью от @elthebestdevelopman-cyber
13. Внесите правки если требуются
14. PR будет смержен после одобрения

## 🎨 Стиль кода

### Именование

- **Классы:** `PascalCase` — `OptimizationEngine`, `MainViewModel`
- **Функции и переменные:** `camelCase` — `optimizeDevice`, `isWorking`
- **Константы:** `UPPER_SNAKE_CASE` — `ADB_TIMEOUT_MS`
- **Пакеты:** `lowercase` — `com.xiaohypercleaner.data`

### Архитектура

- Ручная DI через `AppDependencies` — не добавляйте Dagger/Hilt
- UI только через Jetpack Compose — не добавляйте XML-layouts
- Логи только через `AppLog.i/w/e` — не используйте `Log.d` напрямую
- Все чувствительные данные в логах маскируются через `LogMasker`

### Язык

- Комментарии в коде: русский или английский (оба допустимы)
- Commit-сообщения: английский (стандарт GitHub)
- Документация: русский (основной), английский (по желанию)

## 🧪 Тестирование

### Обязательные проверки перед PR

```bash
# 1. Сборка проходит
./gradlew assembleDebug

# 2. Все тесты проходят
./gradlew testDebugUnitTest

# 3. Lint без ошибок
./gradlew lintDebug
```

### Ручное тестирование

Если изменения затрагивают UI или цепочку оптимизации — проверьте на реальном устройстве:

1. Xiaomi / Redmi / Poco с MIUI 12+ или HyperOS
2. Пройдите [чек-лист из Releases](https://github.com/elthebestdevelopman-cyber/XiaoHyperCleaner/releases)
3. Приложите скриншоты к PR
